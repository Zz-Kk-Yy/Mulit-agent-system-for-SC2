# P0 演示步骤

日期：2026-10-10。按这个顺序在浏览器里走一遍当前已经接上的能力。打开地址用 http://127.0.0.1:8090/ 。完整历史差异和复盘属于后续进展，这一步只看到本轮操作和来源。

## 步骤

1. 打开首页。左上角徽章应显示「合成回放」。左侧是天地图上的厦门市筼筜湖及周边，可以缩放和拖拽。页面不出现「实时」。
2. 确认 U01、P01、L12、巡检队、移动泵没有标在街道上。点成因或依据里的这些编号，页面说明尚无可定位的真实坐标，并显示 L12 → U01 → P01 的空间关联。那是台账拓扑，不是底图上的管线。
3. 打开「水情分析」。事实区应看到最新水深 0.18 m、五分钟上涨 0.08 m、变化速率 0.016 m/min，并写明这不是预报。雨量和潮位是 `--`，未接入。
4. 打开「成因研判」。保留泵故障、管段堵塞待核查、降雨负荷证据不足三个假设。没有雨量时，不把降雨写成已证实原因。
5. 打开「风险评估」。对象是 U01，状态是待核验，等级和官方预警都是 `--`。地图上没有由 0.18 m 画出的淹没面。
6. 打开「应对方案」。能看到 candidate-A 和 candidate-B，耗时和退水效果是 `--`。按钮顺序是「同意方案」「开始演练」「登记结果」。未同意时，后两个按钮不可用，并说明未审批不能派发、尚未派发不能登记结果。页面在派发前不写已执行。说明文字写明演练不会控制真实泵站或设备。
7. 方案保持 candidate-A。点击「同意方案」，再点击「开始演练」。然后为每个任务填写现场说明并点击「登记结果」。登记用的是成功回执。派发文案仍是演练。
8. 打开「分析依据」。能看到这一轮的事件、快照、唯一的观测时间、分析时间、方案审批、演练派发和回执。同一快照再分析不会多出一个观测时刻。规则版本写明未调用大模型。模型未配置或调用失败时，水情数字仍在，模型解释显示失败或待核验，不出现「分析完成」。
9. 打开「历史复盘」。再分析一轮后会出现两个轮次，快照编号相同，观测时间仍是原来的那一个。两轮差异比较还没有做。
