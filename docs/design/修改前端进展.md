# 城市防汛前端改造进展

日期：2026-10-10。本文把 `docs/design/修改前端.md` 拆成可以逐条发给开发助手的进展。方案正文仍以那份文档为准；本文只规定顺序、每一进展要做的内容、可复制提示词和验收标准。

当前基线是 `city_ops/`：单文件 `dashboard/index.html`、`http://127.0.0.1:8090/`、SVG 示意底图、六步时间线和已有审批回执接口。本文各项都还没开始。

## 怎么用

1. 一次只发**一个进展**里的提示词。不要把后面的进展写进同一条提示词。
2. 提示词已经写好，整段复制即可。需要改地图 Key、模型地址时，只替换提示词末尾的「本次环境」两行。
3. 助手做完后，按该进展的验收标准自己点一遍。有一条不通过，就用同一条提示词继续改，不要进入下一进展。
4. 通过后把总表里的状态改成「已验收」，再发下一行。
5. P0 全部验收之前，不做 P1 的时间轴动画、六模块全量和历史对比。P1 全部验收之前，不做 P2 的真实监测接入和淹没面。

## 每一条提示词都要遵守的边界

这些边界来自方案第 0.2 节和第 13 节，后面的提示词不再重复展开，但执行时仍然有效：

- 只在 `city_ops/` 上增量改。保留六阶段计算、`run_id`、`snapshot_id`，以及现有列表、详情、刷新、审批、派发、回执接口的原有语义。
- 合成数据必须显示「合成回放」或「合成演示」，不能显示成实时在线。
- U01、P01、L12、巡检队、移动泵目前没有合法经纬度。真实地图上不画这些点，也不把它们标到厦门街道上。
- 没有雨量、潮位、风险规则、路网或淹没模型时，对应结果保持未知、待核验或不可用。不编造数值、官方预警、最短路径和未来水深。
- 大模型只解释已有证据。它不能改监测值、不能自定风险等级、不能直接调用审批、派发或回执。
- 模型 Key 只放服务端环境变量，不写进 HTML，也不返回给浏览器。
- 观测时间、分析时间、预测时间分开标注。同一快照多次分析是多轮研判，不是水情随时间演变。

## P0-1 拆开前端并搭工作台骨架

**要做的内容**

- 按方案 9.1 节，把 `city_ops/dashboard/index.html` 拆成样式、脚本和页面容器。`city_api.py` 继续从 `/` 返回页面，并为新静态文件返回正确类型。
- 页面改成四个工作区入口：综合态势、智能研判、应急处置、历史复盘。综合态势是默认页。
- 综合态势包含顶栏、概览指标条、左图右栏。右栏先放六个专题标签：综合态势、水情分析、成因研判、风险评估、应对方案、分析依据。
- 原来的六步时间线收进「查看分析流程」折叠面板，不删除。
- 指标条的数字要写清统计口径。只有五个演示对象时就统计这五个，缺测不能显示成 0。
- 保留现有轮次列表、最新轮次、指定轮次和再分析。再分析的按钮文案要说明这是再跑一轮分析，不是刷新现场监测。

**这一进展不要做**

- 不接入地图厂商，不绘制真实经纬度，不调用大模型，不改审批状态机。

**复制这段提示词**

```text
请阅读 docs/design/修改前端.md 第 1、5.1、8.1、9.1 节，以及 docs/design/修改前端进展.md 的「每一条提示词都要遵守的边界」和「P0-1」。只完成 P0-1。

在 city_ops 上增量改造。把 dashboard/index.html 拆成可维护的静态文件，并由 city_api.py 在 http://127.0.0.1:8090/ 继续提供页面。搭出四个工作区：综合态势、智能研判、应急处置、历史复盘。综合态势使用顶栏、有明确统计口径的指标条、左侧地图区和右侧六个专题标签。六个标签先显示来自现有六阶段的事实摘要或明确的未完成状态，不要写成已经调用了大模型。原六步时间线放进「查看分析流程」折叠面板。

保留现有 /api/analysis/runs、/api/analysis/latest、/api/analysis/{run_id}、/api/analysis/refresh 的语义。不要接入地图 SDK，不要调用大模型，不要改审批、派发和回执。

完成后按 P0-1 验收标准自检，列出通过项和未通过项。
```

**验收标准**

- 打开 `http://127.0.0.1:8090/` 能看到四个工作区入口和六个专题标签，右栏不再只有一段流程说明。
- 刷新页面后仍能读到已有轮次；「再分析一轮」会新增一轮，而不是声称监测已更新。
- 折叠面板里仍能按核对数据、计算水情、核对位置、判断原因、给风险、形成方案读完一轮。
- `GET /api/analysis/runs`、`/api/analysis/latest`、指定轮次和 `POST /api/analysis/refresh` 的原有字段仍可使用。
- 页面文件已经拆分，业务脚本不再全部堆在一个 HTML 里。

## P0-2 接入真实底图并隔离合成对象

**要做的内容**

- 在综合态势左侧接入经过许可的真实底图。优先高德 JS API 2.0；如果环境没有可用 Key，就改用已经核过授权的 MapLibre 底图，并在界面标明底图来源。
- 默认视野放在厦门市筼筜湖及周边道路。地图可以缩放、拖拽，并显示真实道路、水体和地名。
- 顶栏用独立徽章显示数据模式。现有 `synthetic_fixture` 显示「合成回放」，不能出现「实时」字样。
- 底图加载失败或 Key 无效时，左侧显示失败原因；右侧已有分析仍可阅读。
- 页面脚注或地图角标写明底图服务名称和授权可见处。不要把 OpenStreetMap 公共瓦片当成已经获准的生产底图。

**这一进展不要做**

- 不把 U01、P01、L12、巡检队、移动泵画到真实地图上。
- 不画风险线、淹没面和抢险路线。

**复制这段提示词**

```text
请阅读 docs/design/修改前端.md 第 2.1、2.2、2.4、10.1、12.1 的 A01、A04、A05，以及 docs/design/修改前端进展.md 的边界和「P0-2」。只完成 P0-2，并保持 P0-1 已完成的工作区不回退。

在综合态势左侧接入真实城市底图，默认定位厦门市筼筜湖及周边。地图必须来自可缩放、可拖拽的地图服务，不能用静态截图或原来的 SVG 冒充。界面标明底图来源。现有合成数据继续显示「合成回放」。当前五个业务对象没有合法经纬度，真实地图上不要出现它们的点位。

地图 Key 从服务端或本地不提交的配置读取，不要写进仓库。没有 Key 或底图加载失败时，左侧给出明确失败状态，右侧分析和旧接口仍可用。不要绘制风险线、淹没面或行动路线。

本次环境：地图服务使用________，Key 的环境变量名是________。

完成后按 P0-2 验收标准自检。
```

**验收标准**

- 人工打开页面后能认出筼筜湖周边的真实道路或水体，并能缩放、拖拽。
- 地图区域没有 U01、P01、L12、巡检队、移动泵的真实位置标记。
- 合成快照下，全页可见「合成回放」或同等含义的「合成演示」，找不到把该数据称为实时在线的文案。
- 断掉地图 Key 或模拟加载失败后，页面仍能打开右侧分析和原六步，并说明地图失败。
- 底图服务名称在页面上可见。

## P0-3 图层目录与无坐标协议

**要做的内容**

- 增加图层目录接口，至少说明道路底图、河湖、设施、监测、水力连接、风险线段是否可用、数据来源和不可用原因。
- 设施和水力连接使用方案 2.4 节的要素结构。现有对象返回 `geometry: null`、`geometry_status: "missing"`，坐标系字段保留为 WGS84，但不要伪造坐标。
- 前端图层开关按「观测、水力、风险、资源、方案」分组。没有几何或没有数据来源的图层可以看见，但处于禁用状态，并写明原因。
- 风险线段接口按方案 8.5 节的字段返回。`geometry_source` 为示意占位时，真实地图不渲染。
- 地图适配层集中处理底图坐标。业务存储保留原始坐标系；送到高德前在适配层转换，不能只改坐标系标签。

**这一进展不要做**

- 不根据单点水深生成道路风险线或淹没多边形。
- 不实现播放动画。

**复制这段提示词**

```text
请阅读 docs/design/修改前端.md 第 2.3、2.4、2.5、8.2、8.5 节，以及 docs/design/修改前端进展.md 的边界和「P0-3」。只完成 P0-3。

为当前演示片区增加图层目录、设施 GeoJSON 和水力连接 GeoJSON。现有 U01、P01、L12 及资源没有合法坐标时，geometry 必须是 null，geometry_status 必须是 missing。前端图层开关分组显示，缺失图层禁用并说明原因。真实地图不得渲染示意占位坐标，也不得根据 0.18 米水深生成淹没面或风险路段。

保留原分析接口。不要做时间轴播放，不要调用大模型。

完成后按 P0-3 验收标准自检。
```

**验收标准**

- 图层接口能逐层返回可用状态、来源和禁用原因。
- 设施接口中的演示对象没有经纬度；真实地图上仍然看不到这些点。
- 关闭或缺少风险几何时，地图不出现彩色风险线，开关旁有文字说明。
- 只有 U01 水深时，响应和页面都不包含二维淹没面。
- 原轮次详情仍能读到 `stages`。

## P0-4 六个专题改为事实卡片

**要做的内容**

- 六个标签都按方案 5.2 节组织：事实、解释、证据与反证、未知项、建议操作。解释区在本进展只写「模型解释尚未运行」，不能生成一段看起来已经分析完成的文字。
- 事实区从现有六阶段映射，不另造数据：
  - 综合态势：异常、待核验数量、五个演示对象的新鲜度。
  - 水情分析：最新水深 0.18 m、五分钟增量 0.08 m、速率 0.016 m/min、观测时间和「不能线性外推」。
  - 成因研判：泵故障有观测支持，管段堵塞待核查，降雨负荷证据不足。
  - 风险评估：U01 为待核验，`level` 为空，不出现官方预警等级。
  - 应对方案：方案 A、B 的任务、资源和未核验条件；未评估的时间和退水效果显示 `--`。
  - 分析依据：事件、快照、六阶段、方案和回执的索引，并保留完整 `run_id`。
- 每个卡片显示缩写 `run_id`、快照编号、数据模式、分析生成时间。缺测显示 `--` 和原因，不用 0 代替。
- 智能研判、应急处置两个工作区复用这些卡片，不复制出另一套数字。

**这一进展不要做**

- 不调用大模型，不把规则原文包装成模型结论。
- 不新增预测虚线。

**复制这段提示词**

```text
请阅读 docs/design/修改前端.md 第 4 章、第 5.2 至 5.8 节，以及 docs/design/修改前端进展.md 的边界和「P0-4」。只完成 P0-4。

把现有六阶段结果映射到六个专题卡片。每张卡片区分事实、尚未运行的模型解释、证据、未知项和建议操作。水情必须准确显示合成快照的 0.18 米、5 分钟上涨 0.08 米、0.016 米每分钟，并写明这不是预报。成因保持泵故障有观测支持、堵塞待核查、降雨证据不足。风险保持待核验且没有等级。方案对比缺少耗时和退水效果时显示两个连字符。

不要调用大模型，不要编造雨量、潮位、未来水深或官方警报。旧六步折叠面板继续可用。

完成后按 P0-4 验收标准自检。
```

**验收标准**

- 六个标签都能打开，并且能看出哪些事实来自现有阶段、哪一块模型解释还没运行。
- 水情卡片上的三个数值、时间和单位与当前快照一致，页面没有「30 分钟后水深」一类外推。
- 成因卡片同时保留三个假设，没有把历史淤积写成已经堵塞。
- 风险卡片没有高、中、低或政府预警颜色结论；等级为空。
- 方案卡片能看到 A、B 和未核验项，缺失评估显示 `--`。
- 分析依据里能复制或看到完整 `run_id`。

## P0-5 地图和卡片双向联动

**要做的内容**

- 地图、专题卡片和证据使用同一个选中对象。点卡片中的设施编号时，如果该对象有真实几何，就定位并保持高亮；如果没有，就打开说明「此资产尚无可定位的真实坐标」，并展示拓扑或证据，不在厦门地图上临时放点。
- 点地图对象时，右侧切到相关专题。没有业务点可点时，这条用有几何的测试要素验证，演示资产仍走无坐标分支。
- 水力关系只在「空间关联」里画已验证的 `L12 → U01 → P01` 拓扑，不把靠近解释成连通，也不把拓扑曲线叠到真实街道上冒充管线。
- 切换轮次后，旧请求的结果不能写进新轮次。
- 图例可以筛选对应实体；被禁用的图层不响应筛选。

**这一进展不要做**

- 不实现播放，不计算抢险路径。

**复制这段提示词**

```text
请阅读 docs/design/修改前端.md 第 2.5、5.9、9.4 节，以及 docs/design/修改前端进展.md 的边界和「P0-5」。只完成 P0-5。

实现地图、专题卡片和证据之间的双向选中。有真实几何才允许定位；演示资产没有坐标时，明确提示不能定位到厦门街道，并仍可查看拓扑和证据。拓扑图单独表达 L12 到 U01 再到 P01，不要画成真实管线。切换轮次时丢弃过期响应。

不要新增时间播放和路径规划。保持合成回放标识。

完成后按 P0-5 验收标准自检。
```

**验收标准**

- 从成因或依据卡片点击 P01、L12、U01，地图不新增点，页面明确说明缺少真实坐标，同时能看到对应证据。
- 用一个带合法几何的测试要素时，点击后地图会定位，右侧会切到相应内容；再点卡片能回到该要素。
- 快速切换两个 `run_id`，后返回的旧轮结果不会覆盖新轮卡片。
- 拓扑图只包含台账里已有的连接，真实底图上没有假管线。

## P0-6 两个可校验的模型研判

**要做的内容**

- 增加 `POST /api/analysis/{run_id}/insights` 和按模块读取的 GET。第一期可以同步返回。`module` 只允许白名单。
- 先真正接通 `hydrology_interpretation` 和 `cause_analysis`。输入由服务端按 `run_id` 组装，浏览器不能提交监测值。
- 按方案 7.5、7.6、7.8 节做结构校验、证据编号校验和领域校验。证据编号先由服务端从现有观测和历史记录生成，不能让模型自造。

- 只有拓扑没有几何的连接不会出现在真实道路上。

## P2-3 内部风险规则与外部警报隔离

**要做的内容**

- 只有经过版本化配置的内部规则才能给风险等级。规则未配置时维持待核验和空等级。
- 页面把内部结果标成「业务规则风险」，并显示规则版本、阈值来源和适用范围。
- 外部官方警报如果没有独立来源，就不显示。以后接入时使用单独区域，写明发布机构、时间和地域，不与内部等级混用颜色含义。
- 受影响道路和建筑没有真实几何及依据时，不统计、不绘制。

**这一进展不要做**

- 不把内部评分叫成政府预警。

**复制这段提示词**

```text
请阅读 docs/design/修改前端.md 第 4.5、10.3 节，以及 docs/design/修改前端进展.md 的边界和「P2-3」。只完成 P2-3。

内部风险等级只能来自有版本的规则配置。没有配置时保持待核验和空等级。配置了测试规则时，页面标明业务规则风险、规则版本和适用范围。没有独立的官方警报来源时，不要显示政府预警。没有几何依据时，不要绘制受影响道路或建筑。

完成后按 P2-3 验收标准自检。
```

**验收标准**

- 删除规则配置后，风险回到待核验，等级为空。
- 启用测试规则后，能看到规则版本，文案不是政府预警。
- 官方警报区域在没有来源时不出现警报内容。
- 模型解释不能把待核验改成高等级。

## P2-4 有模型才接入淹没与情景

**要做的内容**

- 淹没面和预测序列只有在专业模型输出带版本、起报时间和几何来源时才接入。没有输出就保持不可用，不保留看起来能播放的假淹没。
- 预测使用虚线或虚线轮廓，并与观测实线分开。
- 情景只允许修改明确列出的假设参数，例如泵站不能恢复或移动泵是否可用。计算由规则或模型服务完成，模型只解释差异。
- 没有水文水力模型时，情景不返回淹没图、峰值和退水时长。
- 补上权限、审计、限流和错误演练记录中 P2 新增接口对应的部分。

**这一进展不要做**

- 不把情景参数写成真实天气预报。

**复制这段提示词**

```text
请阅读 docs/design/修改前端.md 第 2.6 的积水演化边界、第 6.3、6.5、11.3 节，以及 docs/design/修改前端进展.md 的边界和「P2-4」。只完成 P2-4。

淹没范围和预测序列仅在存在带版本、起报时间和合法几何的模型输出时显示。当前没有这种输出时，图层保持不可用，不要制作演示淹没动画。情景必须展示被修改的参数，并由规则或模型服务计算；没有水文水力模型时，不返回淹没图、峰值和退水时长。预测和观测使用不同线型。

完成后按 P2-4 验收标准自检，并列出仍然需要外部授权才能启用的项目。
```

**验收标准**

- 当前没有模型输出时，淹没图层禁用，播放条中没有预测帧。
- 提供一条带版本和起报时间的测试预测后，预测用虚线，观测仍用实线，两者不会画成同一种数据。
- 情景页面能看到改动了哪个参数；无模型时没有峰值、退水时长和淹没图。
- 情景结果被标成演练假设，不是天气预报。
- 最终说明里分开列出已实现的接口和仍缺授权的数据源。
