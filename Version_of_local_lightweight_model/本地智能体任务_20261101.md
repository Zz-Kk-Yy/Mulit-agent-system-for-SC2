## 3. 联调时怎么连接

2026-11-01 在服务器上看到：用户 `shu1004`，局域网地址 `192.168.1.107`，SSH 监听 `0.0.0.0:22`。地址可能会变。隧道失败时先向服务器要当前地址，不要改成直接访问 `192.168.1.107:8000`。模型端口只绑在服务器本机。

本地执行：

```bash
ssh -L 8000:127.0.0.1:8000 shu1004@192.168.1.107
```

隧道建立后，先确认服务已经由服务器启动，再访问：

```bash
curl -sS http://127.0.0.1:8000/v1/models
```

期望看到模型名 `swarmbrain-qwen3-4b`。看不到就停，不要改服务器配置。

请求体使用 OpenAI 兼容接口：

```json
{
  "model": "swarmbrain-qwen3-4b",
  "messages": [
    {"role": "user", "content": "<Observation 与动作协议>"}
  ],
  "max_tokens": 2048
}
```

`max_tokens` 同时覆盖思考和最终答案。第一次联调用 2048。预热已经证明 128 会把额度用完，最终 `content` 为空。

不要设置 `stop` 为 `</think>`。那样会在最终 JSON 之前停下。  
不要发送 `thinking_token_budget`。服务端不会按这个参数限制思考。  
一局同时只发一个请求。上一个请求没有结束、超时或被取消之前，不发下一条。

## 4. 本地怎样处理返回值

最终动作只从 `content` 读。`reasoning_content` 只作记录，不能执行。

下面任一情况都拒绝执行，并记下原因：

- `content` 为空。
- `content` 不是完整 JSON。
- `finish_reason` 为 `length`。
- 目标数超过 3，或出现协议之外的类型。
- 参数、科技、资源或位置在执行前检查里不成立。
- 请求已过本地期限，或对局已经结束。

协议里的四类目标是 `build_structure`、`expand`、`set_production_target`、`set_army_goal`。空的 `actions` 表示保持当前计划，要单独计数，不能当成模型给出了有效决策。

JSON Schema 目前由本地校验。服务器还没有做约束解码，所以模型可能返回不合格式的文本。格式通过只表示结构合法，资源和前置条件仍要本地再查一遍。

请求元数据由本地程序自己记录，不要要求模型回填，也不要塞进模型 API 的标准字段。至少记录 `game_id`、`request_id`、`observation_id`、`observation_game_time_s`、`plan_epoch`，以及本地单调时钟上的发送时间和期限。延迟用本地时钟计算。不要把本地时间戳和服务器时间戳直接相减。

Observation 至少包含：对局与时间、资源、己方单位与建筑、已知基地和候选扩张点、带时间的敌情、当前计划和最近反馈、允许的目标类型。未看到的敌方数量不能写成 0。调试接口或回放里的全图敌情不能放进推理输入。
